# Fresh Ubuntu setup and complete memory-layer test

**Recommended: [one-command To-do setup](QUICKSTART_DEMO.md)** for Windows/Ubuntu, VS Code Copilot, and Codex CLI/Desktop. The detailed manual steps below remain available for troubleshooting.

Use this guide from start to finish on **Ubuntu with Bash**. All terminal blocks
below are Linux commands. Chat prompt blocks belong in the editor's AI chat, one
at a time. Do not paste PowerShell commands, Windows paths, or `.venv/Scripts`
paths into your Ubuntu terminal.

The primary installation path targets **Ubuntu 24.04 LTS with Python 3.12**.
Other Ubuntu releases can use the managed-Python alternative in section 2.
The project declares Python >=3.11, but this handoff keeps Python at 3.11/3.12
to match the tested dependency setup. The documented Windows results are not
Ubuntu test results: an independent Ubuntu runtime run still needs recording.

## 1. Understand what comes from Git

A local directory listing is not a remote Git file listing. The clone contains
source, tests, scripts, examples, evaluation artifacts, and documentation. These
machine-local paths are not distributed and must be created on Ubuntu:

| Local path | How it is created |
| --- | --- |
| Engine `.venv/` | Create a new Linux environment; do not copy the Windows venv. |
| App `.0xmemory/` | Run `oxmemory init` in the new app. |
| App `.env` | Optional local extraction configuration; not needed for this test. |
| App `.vscode`, `.cursor`, `.agents` MCP configs | Generate using Linux absolute paths. |
| `.pytest_cache`, `.ruff_cache`, `__pycache__` | Generated by tools; not setup inputs. |
| App `data/` | Created when the To-do app saves tasks. |

You can inspect tracked files with `git ls-files`. Do not commit secrets, a virtual
environment, or copied personal editor configurations just to match somebody's
directory listing.

## 2. Install Ubuntu prerequisites

On **Ubuntu 24.04**, open Terminal and run:

```bash
sudo apt update
sudo apt install -y git python3.12 python3.12-venv ca-certificates
git --version
python3.12 --version
```

Ubuntu 24.04 provides [python3.12-venv](https://packages.ubuntu.com/noble/python3.12-venv).
Install project packages inside a venv, not into Ubuntu's system Python.
[Ubuntu Python guidance](https://documentation.ubuntu.com/ubuntu-for-developers/tutorials/python-use/).

**If Python 3.12 is not in your release's repositories:** use an existing Python
3.11/3.12 installation, or install `uv` using its
[official installation instructions](https://docs.astral.sh/uv/getting-started/installation/).
Then run:

```bash
uv python install 3.12
```

In section 3, replace only `python3.12 -m venv .venv` with
`uv venv --python 3.12 --seed .venv`. [`--seed`](https://docs.astral.sh/uv/reference/cli/#uv-venv--seed) supplies pip for the later commands.
This keeps the interpreter separate from the system default.
[uv Python management](https://docs.astral.sh/uv/guides/install-python/).
Do not replace `/usr/bin/python3` or use `sudo pip` / `--break-system-packages`.

Install your editor and sign in to its agent account. VS Code's
[official Linux installation guide](https://code.visualstudio.com/docs/setup/linux)
covers Ubuntu packages. Use the official Linux distribution of Cursor or
Antigravity if selecting those clients. The memory layer needs no Node.js,
Docker, PostgreSQL server, Ollama, or cloud extraction key for this walkthrough.
Hosted coding agents still require their own account and network access.

## 3. Clone and create the environment

Keep this folder layout, with engine and app as siblings:

```text
~/MemoryLayerDemo/
  0xMemory/                  engine clone
    .venv/bin/python         Linux interpreter used by MCP and the app
  testTodoapp/                separate application Git repository
    .0xmemory/               this application's persistent memory
```

**Terminal:**

```bash
set -euo pipefail
demo_root="$HOME/MemoryLayerDemo"
mkdir -p "$demo_root"
cd "$demo_root"
git clone https://github.com/MANOJ-80/0xMemory.git
engine_root="$demo_root/0xMemory"
app_root="$demo_root/testTodoapp"
cd "$engine_root"
git rev-parse HEAD
test -f UBUNTU_SETUP.md
test -f scripts/verify-local.sh
test -f examples/todo-starter/storage.py
python3.12 -m venv .venv
engine_python="$engine_root/.venv/bin/python"
export PYTHONUTF8=1
"$engine_python" -m pip install --upgrade pip
"$engine_python" -m pip install -e '.[dev]'
"$engine_python" -m pip check
"$engine_python" -m oxmemory --help
"$engine_python" -m pip freeze > "$demo_root/installed-packages.txt"
```

If cloning fails because a folder already exists, use a new handoff directory or
inspect the existing clone; do not overwrite it. If the maintainer supplies a
branch, switch to it before installing and record its full SHA. The Ubuntu guide
and scripts must have been published for a fresh clone to contain them.

Activation is optional because commands invoke the venv interpreter explicitly.
If desired, activate using `source "$engine_root/.venv/bin/activate"`.
Quotes protect paths containing spaces. Variables are local to this shell; in a
new terminal, restore them:

```bash
demo_root="$HOME/MemoryLayerDemo"
engine_root="$demo_root/0xMemory"
app_root="$demo_root/testTodoapp"
engine_python="$engine_root/.venv/bin/python"
export PYTHONUTF8=1
```

## 4. Cache embeddings and verify the engine

The first installation needs internet for packages and model weights. Prepare the
same local model used by the tests:

```bash
export HF_HUB_OFFLINE=0
export TRANSFORMERS_OFFLINE=0
"$engine_python" -c "from sentence_transformers import SentenceTransformer; print(SentenceTransformer('all-MiniLM-L6-v2').encode(['memory setup check']).shape)"
```

Expect `(1, 384)`. Only after that succeeds, run the Linux verifier:

```bash
cd "$engine_root"
set -o pipefail
bash scripts/verify-local.sh --skip-install --offline-models 2>&1 | tee "$demo_root/verification.log"
```

The script runs dependency checks, CLI help, **all tests without the Windows
sandbox exclusion**, the temporary Git demo, and real semantic evaluation. The
test collection grows as revisions add tests. Record your actual
count and final PASS line rather than copying the Windows result. Verification
stops at a failed command and saves fresh outputs under `.venv/verification.*`;
it does not overwrite the committed baseline reports.

Use `--skip-install` only after dependencies are installed. Use `--offline-models`
only after caching the model. The script can also create/install an absent Linux
environment with `PYTHON_BIN=python3.12 bash scripts/verify-local.sh`; the explicit
steps above are easier to diagnose for first-time setup. Always invoke it with
`bash`; no executable bit or `chmod` is required. Do not `source` the script.

## 5. Create the fresh application

**Terminal:**

```bash
if [ -e "$app_root" ]; then
  printf 'Choose a new app_root; this application folder already exists.\n' >&2
  exit 1
fi
mkdir -p "$app_root"
cp -R "$engine_root/examples/todo-starter/." "$app_root/"
cd "$app_root"
git init
git add app.py storage.py index.html test_app.py README.md requirements.txt .gitignore .github/copilot-instructions.md AGENTS.md
git -c user.name='To-do Demo' -c user.email='demo@example.invalid' -c commit.gpgsign=false commit -m 'Create JSON-backed To-do task app'
git rev-parse HEAD
"$engine_python" -m oxmemory init --name testTodoapp --local
"$engine_python" -m oxmemory status
"$engine_python" -m unittest -v
```

`cp .../.` includes dotfiles such as `.github` and `.gitignore`. Expect an initial
Git commit, a brain named testTodoapp, **zero memories**, and **five starter tests
passing**. The per-command identity applies only to this demo commit. The CLI's
generic API-key message after init is not a requirement for remember/recall.

Start with the JSON template, not the already-migrated To-do project from another
computer. App tasks live in `data/tasks.json`; decisions live in `.0xmemory`.

## 6. Generate editor configs with Linux paths

**Terminal:**

```bash
"$engine_python" "$engine_root/scripts/configure-editors.py" --project "$app_root" --offline-models --clients vscode codex cursor antigravity
cat "$app_root/.vscode/mcp.json"
```

The helper creates project-local files for the selected clients, merges unrelated settings, rejects conflicting
server entries, and leaves global settings unchanged. It preserves the venv's
Python path even if that interpreter is a symlink to a system binary.

The VS Code result will resemble this, using your actual username:

```json
{
  "servers": {
    "0xmemory-todo": {
      "type": "stdio",
      "command": "/home/alex/MemoryLayerDemo/0xMemory/.venv/bin/python",
      "args": ["-m", "oxmemory", "serve", "/home/alex/MemoryLayerDemo/testTodoapp"],
      "env": {"PYTHONUTF8": "1", "HF_HUB_OFFLINE": "1", "TRANSFORMERS_OFFLINE": "1"}
    }
  }
}
```

The first path is the **engine interpreter**. The final argument is the **app**.
`~` and `$HOME` in arbitrary JSON strings are not shell expansion: use the generated
absolute paths. Do not resolve `.venv/bin/python` to `/usr/bin/python3.12` for the
config; that would lose the installed environment.

| Editor | App-relative config | JSON wrapper |
| --- | --- | --- |
| VS Code Copilot | `.vscode/mcp.json` | `servers`, entry has `type: stdio` |
| Cursor | `.cursor/mcp.json` | `mcpServers` |
| Antigravity | `.agents/mcp_config.json` | `mcpServers` |

**VS Code Copilot:** open the app folder (`code "$app_root"` if the command is
installed), select Agent mode, and use Ctrl+Shift+P > MCP: List Servers. Start
0xmemory-todo, handle its trust prompt, then enable tools in Configure Tools.

**Cursor:** open the same app folder, restart after saving the config, and enable
the server in the MCP management UI (current docs: Customize > MCPs). Select Agent
chat and enable tools. [Cursor reference](https://prod.cursor.com/help/customization/mcp).

**Antigravity:** open the app folder and refresh MCP servers. If your build does
not discover the workspace file, use the agent panel's ... > MCP Servers > Manage
MCP Servers > View raw config and merge the generated entry, preserving existing
entries. The current 2.0 UI also has Settings > Customizations > Installed MCP
Servers. See [EDITOR_SETUP.md](EDITOR_SETUP.md) for the official reference and
version-specific notes.

Use **one editor MCP server at a time** against this brain. The prototype does not
coordinate concurrent Markdown writers. The editor launches stdio; there is no MCP
HTTP port to enter and no separate `serve` terminal to start.

**Agent prompt — connection check:**

## 16. Ubuntu troubleshooting and WSL boundaries

| Symptom | What to check |
| --- | --- |
| `python3.12: command not found` | Use the managed-Python alternative or an installed 3.11/3.12; do not assume every Ubuntu release ships 3.12. |
| `ensurepip` / venv unavailable | Install the matching `python3.12-venv` package, or use `uv venv --python 3.12 --seed .venv`. |
| `externally-managed-environment` | You invoked system pip. Use `"$engine_python" -m pip` inside the project venv. |
| Missing binary wheel / native build failure | Record architecture, Python version, and first package error. Prefer the documented 3.12 setup; do not claim a partial install passed. |
| `Permission denied` running a script | Invoke `bash scripts/verify-local.sh`. Keep the clone in a user-owned directory and do not install the project with sudo. |
| `$'\r': command not found` | Windows CRLF in a shell script. Pull the version with `.gitattributes` LF rules; do not copy a Windows venv. |
| Helper refuses configs | A conflicting server entry or invalid JSON/TOML requires a manual merge; unrelated settings are preserved. |
| MCP cannot launch Python | Check absolute `.venv/bin/python` exists and is executable in the editor's OS context. No `C:/...`, `~`, or unresolved `$HOME` in generated JSON. |
| Different model user/cache | Run model preparation as the same Linux user as the editor; do not download it with sudo. |
| Editor cannot see the server | Open the app folder itself; check wrapper/path, enable tools, restart/refresh, inspect MCP logs. |
| Copilot answers without MCP | Expand the tool call; model prose alone is not proof of retrieval. |
| Old memory stays active | Check evidence file link, committed change, and explicit observe_commit result. |
| Empty context after observation | Expected until stale evidence is reviewed; unrelated active memories may still be returned with the default retriever. |
| Browser does not open on 8090 | uvicorn must be running; MCP startup does not launch the app. |
| `git push` authentication | Unnecessary for the local To-do experiment. Clone public engine source and keep To-do commits local. |

For **native Ubuntu**, run the editor and MCP Python on that same Ubuntu system.
For **WSL**, use a Linux clone and Linux venv, and open VS Code in its WSL remote
context. A Windows-hosted process cannot execute `/home/.../.venv/bin/python`
directly. Other editors' remote-host behavior varies: these instructions do not
claim a Windows-global config launches Linux executables. Test the host context
explicitly or run the editor natively on Ubuntu. Never reuse Windows `.venv` in WSL.
