# Editor setup: VS Code Copilot, Codex CLI/Desktop, and optional clients

**Recommended: [one-command To-do setup](QUICKSTART_DEMO.md)** for Windows/Ubuntu, VS Code Copilot, and Codex CLI/Desktop. The detailed manual steps below remain available for troubleshooting.

Start with [Windows setup](START_HERE.md) or [Ubuntu setup](UBUNTU_SETUP.md) for clone, environment, embedding download,
fresh To-do setup, automatic config generation, and the complete test sequence.
Open the **application folder**, not the engine or its parent, in your editor.
Use the engine's Python executable and the application's absolute path as the
final `serve` argument. The editor launches stdio; no MCP port is required.

| Client | Application-relative config | Wrapper |
| --- | --- | --- |
| VS Code Copilot | `.vscode/mcp.json` | `servers` |
| Codex CLI/Desktop | `.codex/config.toml` | `mcp_servers` (trusted project) |
| Cursor | `.cursor/mcp.json` | `mcpServers` |
| Antigravity | `.agents/mcp_config.json` | `mcpServers` |

Configs generated by START_HERE are local and Git-ignored. They do not change
global editor settings. The manual templates below use example paths: replace
the `YOUR_NAME` paths with your actual engine and app paths.

## Generate configs on Ubuntu

After initializing the app brain and caching embeddings, run from the engine root:

```bash
.venv/bin/python scripts/configure-editors.py --project "$HOME/MemoryLayerDemo/testTodoapp" --offline-models
```

This creates VS Code and Codex local configs with the interpreter running the script and
an absolute app path. Unrelated settings are preserved with backups; conflicting server entries are refused.
Add `--clients vscode codex cursor antigravity` to configure all four clients. Omit `--offline-models` if the model has not
been cached. The helper also works on Windows when invoked with
`.\.venv\Scripts\python.exe` and a Windows app path.

The manual examples below use Windows paths. On Linux, `command` must be the
absolute `/home/YOUR_NAME/MemoryLayerDemo/0xMemory/.venv/bin/python`, and the final
argument must be `/home/YOUR_NAME/MemoryLayerDemo/testTodoapp`. Keep the venv path,
including when it is a symlink; do not replace it with the system interpreter.
See [the complete Ubuntu guide](UBUNTU_SETUP.md) for a Linux JSON example and the
full test. Run the editor in the same OS context as its configured Python.

## Antigravity

Open the application folder and refresh its MCP servers. In the IDE side panel,
use **... > MCP Servers > Manage MCP Servers**. If your installed version does not
discover the workspace configuration, use **View raw config** and merge the
`0xmemory-todo` entry from `.agents/mcp_config.json` into its `mcpServers` object,
preserving existing entries. Refresh and look for the tools. Antigravity 2.0 also
has Settings > Customizations > Installed MCP Servers. Use your build's UI to find
its actual config instead of guessing a legacy global path.

Current docs describe workspace `.agents/mcp_config.json` and the raw-config UI.
Use the same `mcpServers` template as Cursor below.
[Google reference](https://www.antigravity.google/docs/mcp).

In a new chat, ask:

> Use 0xmemory-todo status and report the project name, brain path, and memory counts.

Expand the actual tool call. Follow START_HERE's lifecycle prompts rather than
adding unrelated marker memories to an otherwise empty test brain.

## VS Code with GitHub Copilot

Sign in to Copilot, open the app folder, select Agent mode, and run **MCP: List
Servers** from the Command Palette. Start `0xmemory-todo`, handle its trust prompt,
and enable tools through **Configure Tools**. This targets VS Code's MCP host,
not extension-specific Cline/Roo settings. Current VS Code also documents portable
`.mcp.json` files; avoid duplicate definitions for this test.
[Microsoft reference](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).

Save as `APP_ROOT/.vscode/mcp.json`:

```json
{
  "servers": {
    "0xmemory-todo": {
      "type": "stdio",
      "command": "C:/Users/YOUR_NAME/Desktop/MemoryLayerDemo/0xMemory/.venv/Scripts/python.exe",
      "args": ["-m", "oxmemory", "serve", "C:/Users/YOUR_NAME/Desktop/MemoryLayerDemo/testTodoapp"],
      "env": {"PYTHONUTF8": "1", "HF_HUB_OFFLINE": "1", "TRANSFORMERS_OFFLINE": "1"}
    }
  }
}
```

## Cursor

Save as `APP_ROOT/.cursor/mcp.json`, then restart Cursor. Current UI uses
**Customize > MCPs** for server management and a tools list in Agent chat.
Inspect MCP logs in the Output panel for startup errors. A global
`~/.cursor/mcp.json` is also supported; use the project config for this demo.
[Cursor reference](https://prod.cursor.com/help/customization/mcp).

```json
{
  "mcpServers": {
    "0xmemory-todo": {
      "command": "C:/Users/YOUR_NAME/Desktop/MemoryLayerDemo/0xMemory/.venv/Scripts/python.exe",
      "args": ["-m", "oxmemory", "serve", "C:/Users/YOUR_NAME/Desktop/MemoryLayerDemo/testTodoapp"],
      "env": {"PYTHONUTF8": "1", "HF_HUB_OFFLINE": "1", "TRANSFORMERS_OFFLINE": "1"}
    }
  }
}
```

Use forward slashes in Windows JSON paths; spaces need no extra embedded quoting.
On macOS/Linux replace `command` with the absolute `.venv/bin/python` path. Offline
flags require the model to be cached first. Set them to `0` or omit them when
downloading, then restart the server. No extraction LLM is needed for remember or
recall; `extract` has separate provider requirements. Hosted agents still require
their own account/network access.

Expected tools: remember, recall, list, forget, update, status, extract,
observe_commit, verify_memory, supersede_memory. Initial status should show the
correct app and zero memories; completed experiments should retain their entries.

The starter's `.github/copilot-instructions.md` is for Copilot; other editors are
not assumed to read it. START_HERE's explicit prompts work without assuming shared
instruction-file conventions. MCP availability alone does not guarantee tool use.

## What is and is not confirmed

The developer reported the complete VS Code Copilot lifecycle demonstration;
see [DEMO_RESULTS.md](DEMO_RESULTS.md). Antigravity and Cursor instructions are
based on official references checked on 2026-10-07; their UI/tool runs are not yet
recorded. Use [TEST_REPORT_TEMPLATE.md](TEST_REPORT_TEMPLATE.md) to record them.

Use one editor's memory server at a time for this prototype. The current Markdown
writer does not coordinate concurrent processes; stop its MCP server before
switching editors against the same project memory. Keep the same app path, call
status, then recall in a new chat. Do not reinitialize the brain for a handoff.
