## Interpretation

- Automatic recall invocation is directly visible in the storage screenshot.
- The saved preferences exist on disk and their IDs match the displayed receipts.
- The developer-reported fresh conversation returns the matching naming preference.
- The receipt text is generated by the assistant. It is not a server-signed audit
  trail, and the preference screenshots do not expose raw MCP call results.
- Reading source files also occurred in the reported conversations. This is a
  workflow demonstration, not a controlled attribution or reliability experiment.
- An earlier framework query returned the SQLite decision before the preference
  was saved. Irrelevant retrieval remains a known limitation.

No general success rate, cross-client reliability, or cross-model result is claimed.
The code was locally modified during the run, so a clean engine revision at the
time of execution is not asserted. The containing commit packages the changes and
evidence afterward. Application memories and task data are not included here.

## Rehearsal: ordinary requests

Restart the MCP connection after updating its editable installation, then open a
new Agent chat. Use the configured server and keep its tools enabled.

1. Ask: `Which testing framework does our team prefer for this project?`
2. Establish a genuine new preference in ordinary language. Expect a receipt with
   the saved ID, or an accurate existing-entry report if already saved.
3. Open another chat and ask about that preference without naming its answer or ID.
4. Compare the returned ID and inspect actual tool outputs when available.

Do not present a repeated existing preference as a new save or delete the existing
demo memories to stage a fresh result. See [full demo prompts](../../../DEMO_FLOW.md)
for an isolated fresh-project lifecycle run.
